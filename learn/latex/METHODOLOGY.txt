\chapter{METHODOLOGY}

\section{Overview}

This chapter explains the methodological foundation of CF-MADRL (Clustered Federated Multi-Agent Deep Reinforcement Learning) for decentralized traffic signal control. We describe how the system is organized, how the problem is modeled, how agents learn, how clustered federated aggregation is performed, and how training and evaluation are carried out. Specific implementation values and system parameters are presented in Chapter 5 (Implementation Details).

\section{System Architecture}

CF-MADRL is built from four interacting components that together form a complete learning and deployment loop:
\begin{itemize}
  \item \textbf{Traffic simulation environment:} A microscopic SUMO simulation that provides realistic traffic dynamics and exposes observable features (queue length, waiting time, and phase status) at each step.
  \item \textbf{Local RL agents:} One agent per junction observes its local and shared state, chooses a phase and duration action, and receives a reward signal.
  \item \textbf{Federated learning server:} Aggregates knowledge by clustering agents based on policy weights and performing cluster-wise averaging.
  \item \textbf{Deployment controller:} Executes trained policies either in simulation or on Raspberry Pi hardware, handling safe phase transitions and actuation.
\end{itemize}

\section{Problem Formulation}

\subsection{Decentralized Multi-Agent Setting}

Traffic signal control is naturally decentralized: each intersection has local observations, yet its actions affect neighboring intersections through vehicle flow. In CF-MADRL, each junction is controlled by an independent agent. This improves scalability and robustness because there is no single central controller that must process the entire network, and each junction can continue operating even if communication is limited.

\subsection{Decentralized MDP}

Each junction $i$ is modeled as an MDP:
\begin{equation}
M_i = \langle S_i, A_i, P_i, R_i, \gamma \rangle
\end{equation}
Here $S_i$ is the state, $A_i$ is the action space, $P_i$ is the transition dynamics, $R_i$ is the reward, and $\gamma$ is the discount factor. The learning objective is:
\begin{equation}
J_i(\pi_i) = \mathbb{E}\left[\sum_{t=0}^{\infty} \gamma^t R_i(s_t, a_t, s_{t+1})\right]
\end{equation}
Because all agents are learning at the same time, the environment is non-stationary. Clustered federated aggregation helps stabilize learning by synchronizing policies within groups of similar agents.

\section{State, Action, and Reward Design}

\subsection{State Space}

At each time step, agent $i$ observes both local traffic and shared upstream signals. For each incoming lane $l$, the state includes queue length $q_{i,l}$ and waiting time $w_{i,l}$. Shared components $q^{\text{shared}}_{i,l}$ and $w^{\text{shared}}_{i,l}$ are computed from upstream junction metrics and weighted by turn ratios estimated from outgoing-lane vehicle counts. The current traffic light phase $\phi_i$ is appended as a normalized scalar so that the agent knows its present control state.

States are padded to a fixed maximum lane count $L_{\max}$ and form:
\begin{equation}
\mathbf{s}_i^t = [\mathbf{q}_i, \mathbf{w}_i, \mathbf{q}_i^{\text{shared}}, \mathbf{w}_i^{\text{shared}}, \phi_i^{\text{norm}}]
\end{equation}

\textbf{Normalization.} We apply constant scaling for both training and deployment: $\hat{q} = q/15$ and $\hat{w} = w/300$. The constants 15 and 300 are computed from the number of vehicles observed in the network. Shared components are weighted by $\alpha_s = 0.5$ before scaling and all values are clipped to $[-10, 10]$.

\subsection{Action Space}

Actions are discrete and encode both phase selection and green duration. With $n_d=7$ durations and $n_p$ valid green phases, the action is decoded as:
\begin{equation}
\text{dur\_idx} = a \bmod n_d, \quad \text{phase\_idx} = \lfloor a/n_d \rfloor \bmod n_p
\end{equation}
This representation supports junctions with different phase counts while keeping a unified action space.

\subsection{Reward Function}

The reward penalizes congestion and waiting time:
\begin{equation}
R_i = -\frac{Q_i + 0.5 W_i}{L}
\end{equation}
where $Q_i$ is total queue length, $W_i$ is total waiting time, and $L$ is the number of lanes. A reward floor is applied to prevent extreme spikes and stabilize learning.

\section{Agent Learning Algorithms}

\subsection{PPO Actor-Critic}

Each junction runs an independent PPO agent. The actor $\pi_\theta(a|s)$ outputs an action distribution, while the critic $V_\phi(s)$ estimates the value function. PPO optimizes the clipped surrogate objective:
\begin{equation}
L^{\text{CLIP}}(\theta) = \mathbb{E}_t\left[\min\left(r_t(\theta)\hat{A}_t, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t\right)\right]
\end{equation}
where $r_t(\theta)$ is the policy ratio and $\epsilon$ is the clip parameter. Advantages are computed using GAE to balance bias and variance.

\subsection{Baselines}

Two baselines are used for comparison:
\begin{itemize}
  \item \textbf{Q-Table:} A tabular Q-learning agent with discretized state features and epsilon-greedy exploration.
  \item \textbf{DQN:} A deep Q-network with replay buffer and target network updates, trained independently per junction.
\end{itemize}

\section{Clustered Federated Learning}

\subsection{Weight-Based Clustering}

Agents periodically upload their policy weights to the server. The server flattens weights into vectors and clusters them using K-Means. Let $w_i$ be the weights of agent $i$ and $\mathcal{C}_k$ be cluster $k$. Cluster centroids are computed as:
\begin{equation}
\mu_k = \frac{1}{|\mathcal{C}_k|} \sum_{i \in \mathcal{C}_k} w_i
\end{equation}

\subsection{Cluster-Wise Aggregation with Soft Blending}

Within each cluster, FedAvg is applied:
\begin{equation}
W_k = \frac{1}{|\mathcal{C}_k|} \sum_{i \in \mathcal{C}_k} w_i
\end{equation}
Each agent receives a blended update:
\begin{equation}
\tilde{w}_i = (1-\alpha) w_i + \alpha W_k
\end{equation}
where $\alpha$ controls the contribution of the cluster average. This preserves local specialization while enabling knowledge transfer among similar junctions.

\section{Training Protocol}

Training is organized into federated rounds. In each round, all agents interact with the shared SUMO environment for a fixed number of steps, update their local policies, and then synchronize via clustered aggregation. Early stopping is applied based on average reward improvement, and checkpoints are saved periodically. Baseline agents follow the same environment and step count to ensure fair comparison.

\section{Evaluation Protocol}

Evaluation runs each agent under the same simulation settings and records per-junction metrics (rewards, queue length, and waiting time). Fixed-time control is included as a non-adaptive baseline. Detailed comparisons and results are reported in the Results chapter.

\section{Hardware Deployment Method}

For real-hardware deployment, ESP32 cameras stream video to a Raspberry Pi. The Pi runs vehicle detection, constructs the state vector, performs PPO inference, and returns a phase decision through a FastAPI endpoint. The ESP32 applies the phase and duration, optionally inserting a yellow interval when a phase switch is required. This hardware loop mirrors the simulation control cycle while using real traffic observations.
